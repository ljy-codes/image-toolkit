# 苏影枢质量修复轮验收报告

- 日期：2026-09-03
- 范围：开发空间质量修复与本地验收
- 当前状态：本轮开发验证及本地正式交付已完成，未提交或推送 GitHub

## 验收原则

1. 普通处理不包含 AI 推理，必须保持界面响应，单图耗时应短，批量只允许总耗时随数量增长。
2. AI 抠图允许耗时较长，以主体完整、边缘质量和复杂细节保留为优先目标。
3. 压缩目标无法达到时必须判定为未处理，不得保留超标输出，并向用户展示明确原因。
4. 自动化指标、真实图片处理和人工目视检查必须同时记录，不能仅凭测试用例数量判定质量。

## 已确认事实

- 普通处理的 CPU 工作原先可能在 WPF UI 同步上下文中执行，这是单图也出现“未响应”的主要原因。
- 旧 AI 推理代码固定使用 `320x320` 输入，无法正确利用高分辨率模型。
- 旧背景逻辑会持续强制透明 PNG，导致白色、黑色和自定义背景选择失效。
- 产品介绍 HTML 的超宽屏 Hero 使用视口宽度参与容器内边距计算，可能把正文压成一列。
- Wikimedia 搜索结果存在场景标签噪声，因此性能集可以全量使用，AI 质量集必须人工筛选明确主体。

## AI 验收

基础真实图片结果：

- 通用模型单图约 29 秒。
- 人像模型单图约 41 秒。
- 通用模型 3 张批量约 62 秒。
- 昆虫腿、触角和翅膀得到保留；白底和蓝底合成未见原先的白色散点。
- 人像主体完整，发丝保留软边；白衬衫属于原始前景，不作为白边误判。

多场景最终验收：

- 15 张明确主体图片全部生成有效透明 PNG，完整运行耗时 3 分 50 秒。
- 1 张主体不明确的纯风景图按预期拒绝，耗时约 23 秒；错误原因明确说明未识别到可稳定保留的主体，且不生成输出文件。
- 蝴蝶多主体、食蚜蝇透明翅/细腿和车轮细辐条专项通过，耗时约 57 秒。
- 蝴蝶图的前景连通域由修正前 51 个降到 13 个，10 个主要蝴蝶主体保留，编号等小标注基本清除。
- 建筑、相机、猫、食物、植物、壁虎、多人、昆虫、人像、手机、树和车轮等场景目视结果可用。
- 夜景游乐设施会保留部分灯杆；车辆与人物混合图更倾向保留人物和车窗区域。这两项属于模型语义边界，未伪装为已解决。

## 剩余问题与风险

1. 夜景、霓虹灯、复杂机械与人物/车辆混合场景仍可能出现主体语义选择不符合用户预期；当前没有交互式点选主体或蒙版画笔。
2. 当前真实图片没有逐像素人工标注蒙版，无法给出 IoU 等客观分割精度；本轮采用透明比例、连通域、主体保留和深浅背景目视检查组合验收。
3. WPF 页面已通过编译、ViewModel 测试和静态布局检查，但本轮为避免频繁弹出窗口，没有代替用户完成最终鼠标交互体验验收。
4. 100 张图片集覆盖 16 个检索场景并保留来源和许可记录，但 Wikimedia 检索标签存在噪声，文件名前缀不能等同于真实内容标签。
5. AI 模型约 928 MiB/个，首次下载和磁盘占用较大；模型保持可选，不影响未启用 AI 的普通处理速度。
6. AI 推理当前以准确和稳定为优先，单张约 14 至 41 秒；大型模型并发受控，避免内存争抢导致应用假死。
