# 苏影枢 v1.1.0 质量修复与 AI 抠图设计

**日期：** 2026-09-02  
**状态：** 待用户确认  
**开发目录：** `D:\专用工具\图批处理\开发空间`  
**问题基线：** `docs/releases/v1.1.0-issue-tracking.md`

## 1. 目标

本版本在不破坏 v1.0.0 现有尺寸、裁剪、背景、格式转换和批量处理能力的前提下，完成以下目标：

- 修复深色下拉框、目标大小压缩、批次残留和卡顿等实际使用问题。
- 重新组织参数区，使功能名称、作用和开关状态清晰。
- 增加参数初始化及本机命名预设。
- 按单文件和文件夹来源执行明确的默认输出规则。
- 加入人像及商品/普通物体两类本地 AI 抠图。
- 更换应用图标，并统一应用与安装器的深色视觉。
- 为最终 `v1.1.0` Release 准备完整内容，但在用户最终同意前不生成正式交付物、不推送 GitHub。

## 2. 实施策略

采用“分阶段开发、一次正式发布”：

1. 正确性与稳定性：压缩、输出路径、批次生命周期、卡顿诊断。
2. 参数体验：说明文本、保留原尺寸、初始化、命名预设、错误详情。
3. AI 抠图：模型管理、双模型推理、透明背景输出。
4. 视觉统一：深色控件、专业图标、安装器深色主题。
5. 全量验证：自动测试、用户样图、本机安装测试。
6. 最终门禁：提交验证报告，等待用户同意后才生成交付物并发布。

不做全仓库重构，不改变现有分层方向，不将模型文件提交到 Git。

## 3. 主界面设计

### 3.1 工作区

保持单窗口工作台，但调整操作层级：

- 顶部：添加图片、添加文件夹、开启下一批、清空列表、预设选择。
- 中部：原图/效果预览与当前文件信息。
- 下部：批次文件列表、每项状态、输出路径和详细失败原因。
- 右侧：处理参数，按功能分组。
- 底部：成功、未处理、跳过数量，整体进度，开始、暂停、取消。

### 3.2 功能说明

每个参数分组必须包含一行简洁说明：

- 压缩：将文件控制到指定大小；严格模式下未达到目标不会生成输出文件。
- 尺寸：默认保留原图尺寸，开启后可按宽高、比例或长短边调整。
- 格式：转换图片格式，并处理透明通道与背景兼容。
- 背景：为透明图片填充纯色或保留透明。
- AI 抠图：在本机识别人像或物体主体，并生成透明背景。

说明直接显示，不依赖鼠标悬停。高级说明可以使用信息图标展开。

### 3.3 尺寸参数

- 默认显示并选中“保留原尺寸”。
- 选择“调整尺寸”后才启用模式、宽度、高度和长短边字段。
- 未启用尺寸调整时，不执行宽高必填校验。
- 切回“保留原尺寸”时保留用户最近填写值，但本轮不使用。

### 3.4 深色下拉框

为 `ComboBox` 和 `ComboBoxItem` 提供完整模板，不依赖系统默认弹出层：

- 输入区、下拉弹层、选项背景和文字均使用深色主题资源。
- 明确普通、悬停、选中、禁用和键盘焦点状态。
- 选中项不能只靠颜色区分，增加勾选图标或左侧标记。
- 弹层边界、最大高度和滚动条保持清晰。

### 3.5 批次结束

处理完成后在结果区域提供：

- `开启下一批`：清空文件、结果、预览和进度，保留当前参数或已选预设。
- `清空列表`：清空当前队列，执行前二次确认未完成任务。
- `打开已处理目录`：仅在存在输出时显示。
- `查看失败原因`：聚焦或筛选未处理项目。

添加新文件时，如果上一批已结束且仍有记录，先提示“追加到当前结果”或“开启下一批”，避免混淆。

## 4. 严格目标大小压缩

### 4.1 业务规则

- 设置目标大小后，最终文件字节数必须小于或等于目标字节数。
- 编码、质量搜索、允许的尺寸搜索全部完成后仍超标，返回 `TargetSizeUnmet`。
- `TargetSizeUnmet` 属于未处理，不属于成功。
- 不将超标结果写入正式输出路径。
- 清理临时文件，原文件保持不变。

### 4.2 PNG 策略

PNG 默认先执行无损优化。若无法满足目标：

1. 用户已允许颜色量化时，执行颜色数量搜索。
2. 用户已允许缩小尺寸时，执行分辨率搜索。
3. 用户允许转换格式时，尝试 JPEG 或 WebP。
4. 所有允许策略耗尽后，严格判定未处理。

不静默启用有损策略。

### 4.3 结果对象

处理结果增加结构化诊断信息：

```text
ErrorCode
Stage
UserMessage
TechnicalMessage
TargetBytes
BestAttemptBytes
OriginalDimensions
AttemptedDimensions
Suggestions[]
OutputCreated
```

页面直接展示用户信息和关键数值；技术信息放入可展开详情，并写入日志。

## 5. 输出路径与失败归档

### 5.1 来源上下文

导入结果不再只保存平铺文件列表，同时保存：

```text
ImportBatchId
ImportKind: File | Folder
SourceRoot
RelativePath
SourcePath
```

输出解析器根据来源类型生成路径，而不是根据单个文件临时推断。

### 5.2 单文件

- 成功：同目录 `文件名-已处理.扩展名`。
- 失败：不生成输出，不复制文件，原文件不动。
- 同名冲突：追加递增序号，不覆盖已有结果。

### 5.3 文件夹

- 成功：同级 `原文件夹-已处理`，保留相对子目录结构。
- 失败：将原始文件复制到同级 `原文件夹-未处理`，保留相对子目录结构。
- 失败目录生成 `失败原因.csv` 和便于阅读的 `失败原因.txt`。
- 失败清单包含源文件、失败阶段、用户原因、建议、错误代码和时间。
- 失败归档复制异常不能覆盖原处理异常，两者分别记录。

## 6. 参数初始化与命名预设

### 6.1 默认参数

增加 `恢复默认参数` 命令：

- 恢复内置默认值。
- 不清空文件队列。
- 有未保存的预设修改时提示确认。

### 6.2 命名预设

增加本机预设库：

- 新建、另存为、更新、重命名、删除。
- 预设名称唯一，忽略前后空格。
- 内置“默认参数”只读。
- 记录预设版本，旧版本配置通过迁移器读取。
- 预设仅保存处理参数，不保存输入文件、输出历史或模型下载进度。

配置仍保存于 `%LOCALAPPDATA%\ImageToolkit`，写入采用临时文件加原子替换；损坏时备份并回退默认配置。

## 7. AI 抠图

### 7.1 用户流程

1. 用户开启 AI 抠图。
2. 选择“自动识别”“人像优先”或“商品/物体优先”。
3. 所需模型未安装时显示模型用途、体积、许可证和本地隐私说明。
4. 用户确认后下载，显示进度、速度、剩余大小和取消入口。
5. 下载完成后校验 SHA-256，再原子安装。
6. 模型安装后在本机推理，输出透明背景。

### 7.2 双模型结构

- 人像模型 Adapter：针对头发和半透明边缘。
- 通用物体模型 Adapter：针对商品、物品和普通主体。
- 自动识别先使用低成本图像特征或用户来源提示选择模型；第一版不同时运行两个大模型后再比较。
- 模型选择、预处理、推理和后处理均通过现有 `IBackgroundRemovalEngine`、`IAiModelManager` 扩展实现。

### 7.3 模型选型门禁

具体模型必须同时满足：

- 许可证允许随 MIT 应用合法使用和分发下载信息。
- 存在可复现的 ONNX 模型或可验证转换流程。
- SHA-256、下载地址、版本和来源写入 Manifest。
- 在目标 Windows 11 x64 CPU 环境完成内存、速度和质量基准。
- 不满足许可证或基准要求的模型不得进入正式版本。

模型按需下载，不进入安装包、不进入 Git 仓库。

### 7.4 稳定性

- ONNX Session 按模型复用，但同一模型限制并发推理数量。
- 下载、校验和推理均支持取消。
- AI 失败只影响当前任务，不使普通处理流水线崩溃。
- 模型未安装或损坏时，普通尺寸、格式和压缩功能仍可使用。

## 8. 卡顿治理

当前优先排查预览刷新与批处理争用：

- 预览采用 single-flight，新的预览请求取消并替代旧请求。
- 参数连续变化使用防抖，取消请求不能继续占用 UI 更新通道。
- 批处理运行时降低或暂停高成本实时预览。
- Magick 和 ONNX 操作放到受控后台调度器，限制 CPU 与内存并发。
- 每张图记录开始、阶段耗时、内存异常、取消和结束状态。
- 主线程只执行 UI 状态更新，不执行图片 Decode、Encode 或推理。
- 取消超时后给出明确提示，不让界面长期停留在“处理中”。

先通过用户样图和压力测试复现，再按日志证据修复，避免只调整表象。

## 9. 图标与安装器

### 9.1 应用图标

图标概念采用“画面框 + 处理焦点/层叠效果”，避免通用齿轮或模糊图片符号：

- 主形简洁，适用于 16、24、32、48、64、128、256 像素。
- 深色和浅色任务栏均能识别。
- 同一 ICO 用于 exe、窗口、任务栏、快捷方式和安装器。
- 构建时验证各尺寸图层存在。

### 9.2 安装器深色模式

- 安装器主体、标题、说明、路径框、任务列表和底部按钮统一深色。
- 列表和文本框必须自定义前景、背景及禁用态，避免系统默认浅色子控件。
- 保留 Windows 标准安装、取消、上一步、卸载和权限行为。
- 若现有 Inno Setup 无法可靠覆盖必要控件，则先做技术验证，再决定使用自定义向导页面或更适合主题化的安装器；不为视觉效果牺牲安装稳定性。

## 10. 兼容性

- 现有 v1.0.0 配置可读取并迁移。
- 现有命令和普通图片处理流程继续可用。
- 输出默认规则发生变化，需要在更新日志中明确说明。
- 严格压缩会将过去的“超标但输出”改为“未处理且不输出”，属于有意行为修正。
- AI 为可选功能，未安装模型时不影响基础功能。

## 11. 测试设计

### 11.1 自动化测试

- 深色 ComboBox 状态资源及关键绑定测试。
- 保留原尺寸和启用尺寸调整的验证测试。
- 严格压缩成功、未达标、临时文件清理测试。
- 单文件和文件夹来源的输出路径测试。
- 失败文件复制、子目录保留及失败清单测试。
- 下一批清理状态但保留参数测试。
- 默认参数和命名预设的增删改查、迁移及损坏回退测试。
- AI Manifest、下载取消、哈希失败、安装回滚及 Adapter 选择测试。
- 预览 single-flight、批次取消和并发上限测试。

### 11.2 人工验证

- 使用用户约 2.15 MB PNG，目标设为 1 MB，确认成功结果不超标；不能满足时明确未处理且无超标文件。
- 连续执行两批，确认上一批内容不干扰下一批。
- 快速连续修改参数并启动批量处理，确认窗口可响应。
- 验证深色下拉框所有状态可读。
- 验证人像、头发边缘、商品、复杂普通物体和透明输出。
- 验证模型未安装、断网、下载中断、哈希失败和磁盘不足。
- 最终阶段才执行全新安装、升级、卸载和交付目录检查。
